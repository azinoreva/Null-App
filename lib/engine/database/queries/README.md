# `lib/engine/database/queries` — Drift DAOs (Query Layer)

One DAO per table (some files hold more), each extending
`DatabaseAccessor<AppDatabase>`. These are the **only** sanctioned way to read
and write the database from application code — screens, engine tasks, and
providers all go through these DAOs, never raw SQL.

Each `*_queries.dart` file has a matching `*_queries.g.dart` generated by
`dart run build_runner build` (do not edit the `.g.dart` files).

## DAOs and their highlights

| File | DAO | Notable behaviour |
|---|---|---|
| `identity_queries.dart` | `IdentityDao` | Single-row table for the current user. `getCurrentIdentity()`, and a long list of `setX(...)` partial updates (display name, bio, avatar, phone, public key, security settings, etc.). |
| `servers_queries.dart` | `ServersDao` | Server CRUD plus media accounting (`incrementMediaSent`, `resetMediaUsage`), `updateCapabilities`, and `getAllDistinctColours()` (used by the distinct-colour picker). |
| `conversations_queries.dart` | `ConversationsDao` | Conversation CRUD, `getConversationsByLastMessage()`, `updateDraft`, `incrementUnread`, `setBadge`. |
| `messages_queries.dart` | `MessagesDao` | Message CRUD with the pagination/ordering hooks used by the UI: `getMessagesForConversationPaginated`, `getLastMessages`, `getMessagesBeforeOrder`, `getMessagesAfterOrder` (incremental append), `getLatestMessage`, `insertMessages` (atomic batch). |
| `contacts_queries.dart` | `ContactsDao` | Contact CRUD, connection-status filtering (`getConnectedContacts`, `getOnlineConnectedContacts`), notification flags (`setMuted`, `setPinned`), presence (`setOnlineStatus`, `updateLastSeen`), `setPublicKey`, `setConversationId`, `updateAvatar`, `upsertContact`. |
| `network_queries.dart` | `ContactsNetworkDao` + `ContactNetworkMembersDao` | Network CRUD and membership juncion helpers (`isMember`, `getContactIdsInNetwork`, `getNetworkIdsForContact`). |
| `groups_queries.dart` | `GroupsDao` | Group CRUD plus the **key-rotation** plumbing used by the crypto layer: `getGroupsWithPendingKeyRotation`, `getGroupsReadyForKeySwap`, `scheduleKeyRotation`, `cancelKeyRotation`, `activatePendingKey` (atomic promotion), `updatePrivateKey`. |
| `group_members_queries.dart` | `GroupMembersDao` | Composite-key membership CRUD and per-member field updates (name/bio/avatar/public key), `getMemberPublicKey`, `getGroupsOfIdentity`. |
| `connection_requests_queries.dart` | `ConnectionRequestsDao` | Request CRUD/status transitions (`acceptRequest`, `rejectRequest`, `rejectExpiredRequests`), filtering by requester/recipient/group. |
| `tasks_queries.dart` | `TasksDao` (+ `TaskStatus`, `TaskKind` consts) | The task engine's workhorse. `getNextPendingTask({networkAvailable})` picks fresh-before-retry, network-first work with network gating; `claimTask` (atomic pending→in-progress), `markTaskCompleted`, `incrementRetryCount`, `requeueForRetry`, `markTaskFailed`, `getUnsyncedTasks`, `updateSyncFlags`. |
| `shamirs_secret_queries.dart` | `ShamirsSecretDao` | CRUD for per-recipient Shamir recovery rows. |
| `secret_share_queries.dart` | `SecretShareDao` | CRUD plus `recordShare(...)` for the last-shared/version bookkeeping. |
| `sync_state_queries.dart` | `SyncStateDao` | The conversation-list mirror: `watchAllSyncStates()` / `watchSyncStateById()` (reactive streams that back the Riverpod providers), `getAllSyncStates` (pinned first, then `updatedAt` desc), `markAllRead`, `updateLastRead`, `updateLastMessage`, `updateDraft`, `setPinned`, `updateColour`, `setMuted`, `setMentions`. |

## Conventions

- Prefer the purpose-built mutators (e.g. `markTaskCompleted`) over raw
  `insert`/`update` where one exists — they encode intent and often partial
  updates care about whole-row replacement.
- `TaskStatus` constants (`tasks_queries.dart`) are authoritative for task
  state: `0 pending, 1 inProgress, 2 completed, 3 failed, 4 cancelled`.
  (`TaskKind`: `0 nonNetwork, 1 network`.)
- Typed streams (`.watch*`) exist for the UI tables (`SyncState`) and are what
  the state layer in `lib/state/providers.dart` subscribes to.
